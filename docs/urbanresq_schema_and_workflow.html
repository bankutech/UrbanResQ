1. System Overview

UrbanResQ is a full-stack decision-support platform for coordinating urban disaster response. It manages the complete lifecycle from disaster declaration through emergency request intake, intelligent resource allocation, rescue team dispatch, hospital/shelter management, and post-event analytics.

Core Capabilities

  • Real-time Dashboard — live stats, charts, and activity feed for situational awareness
  • Command Center — interactive disaster map with heatmaps, emergency queue, resource panel
  • Allocation Engine — stored procedure that optimally matches resources to requests using priority scoring
  • What-If Simulation — dry-run scenarios that don't affect production data
  • Citizen Reporting — public-facing form with optional AI image assessment
  • Drone Surveillance — live HUD overlay with detection bounding boxes
  • RBAC Security — JWT tokens, 7 distinct roles, permission-based route guards

5. Allocation Engine Workflow

The allocation engine is a MySQL stored procedure (sp_generate_resource_allocation_plan) that serializes access via a named lock.

1. Acquire Lock
GET_LOCK('allocation_engine_lock', 20) — serializes concurrent calls
↓
2. Score Requests
Priority = f(urgency, vulnerability, wait_time, people_affected)
↓
3. Match Resources
Nearest inventory with available stock, scored by distance + criticality
↓
4. Dispatch Teams
Assign available rescue teams by specialization match
↓
5. Detect Shortages
Flag resources that fall below min_threshold
↓
6. Commit or Rollback
p_dry_run = 0 → COMMIT, p_dry_run = 1 → ROLLBACK (simulation)
↓
7. Release Lock
RELEASE_LOCK('allocation_engine_lock')

8. Stored Procedures

ProcedureParametersPurpose
sp_generate_resource_allocation_plan p_disaster_id INT, p_user_id INT, p_dry_run BOOLEAN Core allocation engine. Scores pending requests by priority, matches nearest available resources, dispatches rescue teams, detects shortages, and either commits or rolls back (simulation mode).
sp_admit_patient p_hospital_id, p_patient_name, p_condition, p_needs_icu, p_request_id Admits a patient to the nearest available bed, auto-selects ICU if needed, decrements available bed counts.
sp_check_in_resident p_shelter_id, p_full_name, p_citizen_id Registers a displaced resident at a shelter, increments occupancy, enforces capacity constraints.
